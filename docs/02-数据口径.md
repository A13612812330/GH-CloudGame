# 02 · 数据口径

> 这份文档定义了「怎么算才是对的」。口径错了，后面所有数字都白做。
> 每条规则都附了真实的翻车案例，不要跳过。

---

## 一、跨期对比：本期两周 vs 上期两周

**唯一正确的对比方式**：

```
环比 = 本期两周合计 ÷ 上期两周合计 − 1
```

**不是**本期内部 W1 vs W2。

### 真实翻车

> 2026-09-28 曾把「本期 9.14-9.20」与「本期 9.21-9.27」对比，得到
> 搜索 **+39.9%**、下载 **+44.2%** —— 全部作废。
> 正确的跨期值是搜索 **+1.5%**、下载 **−11.5%**。

判断方法很简单：**看目录**。数据目录是按期次组织的（`9.14-9.27/`、`9.28-10.11/`），
所以「本期」= 当前交付的这一期，「上期」= 上一份报告覆盖的那一期。

---

## 二、两期粒度必须先自证

两期的导出方式**可能不同**，直接比会得到离谱的数字。

### 实测差异

| 期次 | 下载源导出形式 |
|---|---|
| 8.31 – 9.13 | 2 个日期列 = **周汇总**（8.31-9.6 / 9.7-9.13 各一周） |
| 9.14 – 9.27 | **14 天逐日** |
| 9.28 – 10.11 | **14 天逐日** |

### 自证方法

取两期**共有游戏**，计算：

```
比值 = Σ(本期各日数值) ÷ Σ(上期各列数值)
```

取**中位数**。若 ≈ 1，说明两期时间跨度等效，可直接比。

> 2026-09-28 实测：405 款共有游戏，该比值中位数 = **1.014 ≈ 1** ✅
> 若比值是 0.1 或 10 这类数量级差异，说明一期是周汇总、一期是逐日，
> **必须先找数据提供方确认导出方式，不要硬比**。

### 反向验证（推荐习惯）

用同一套清洗逻辑跑一遍**上期**数据，看能否精确复现上期报告的 KPI。
能复现 ⇒ 口径没有漂移。

## 三、搜索源：每列代表一周

搜索表「明细数据」sheet 每期含 **2 个日期列**（通常是两个周一）。

- 每个日期列 = **该周的汇总**，不是单日
- 两列相加 = 该期两周总量

所以本期（14 天）与上期（2 列 × 7 天）时间跨度等效。

---

## 四、关键词清洗：三级匹配

把用户输入的搜索词归到游戏名上，规则优先级从高到低：

| 级别 | 规则 | 例子 |
|---|---|---|
| **精确** | 完全等于词库里的某个别名 | `我的世界` → 我的世界 |
| **前缀扩展** | 以某游戏名开头，且长度差 ≤ 6 字 | `方舟生存进化` → 方舟 |
| **词根中断** | 是某游戏名的截断，且截断部分 ≥ 3 字 | `我的世` → 我的世界 |

### 护栏

- **双字泛词必须排除**：`恐怖`、`我的`、`植物`、`超人` 这类词会吃掉大量无关流量。
  放在 `assets/endgame_lib.json` 的 `exclude` 里。
- **按最长前缀归并**：`ROB` / `ROBLO` / `ROBOX` 都归 ROBLOX，不要各自成条。
- **别名冲突要人工裁决**：一个别名只能指向一个游戏。

### 已知的归属不确定

> `OVER` / `OVERP` / `OVERPE` 这类**截断词**同时可能是
> `OVERWATCH`（守望先锋）和 `OVERPEAK` 的前缀，无法从数据上区分。
>
> 因两期使用**同一套词库**，跨期趋势不受影响，但**绝对归属存疑**，报告中应注明。

### 词库维护

`assets/endgame_lib.json`：

```json
{
  "endgame": { "游戏名": ["别名1", "别名2"] },
  "exclude": ["恐怖", "我的", "植物", "甜瓜"]
}
```

⚠️ `exclude` 是**全局**的。如果某游戏名包含被排除的词，它永远不命中
（例：`甜瓜游乐场` 因 `exclude` 含 `甜瓜` 而无法计数）。要么解开冲突，要么接受漏记。

## 五、端手游混流（神策搜索源的最大陷阱）

**神策搜索源不区分端游 / 手游。** 跨端外溢会污染端游榜。

### 真实案例（2026-10-12）

《OVERPEAK》搜索 **318,165** 次、跨期 +1082%，跃居端游搜索第 2。但它**不是端游**：

- 中文名「巅峰崛起」，玩家称「祖国人模拟器」
- 包名 `com.rusergames.overpeak`，安装包约 **300MB**（手游量级）
- Steam 同名 appid 峰值仅 **94**
- 国内渠道站自 10/6 起集中铺下载页 ⇒ 热度来自移动端与短视频导流

### 判定三步法

1. 搜「游戏名 + 手游下载」，看 3DM / 西西 / 逗游等渠道站是否**集中上架**
2. 看**包名 / 安装包体积**（300MB 量级 ≈ 手游）
3. 比对 Steam 同名 appid 的**真实在线人数**

> **凡某「端游」搜索出现异常脉冲，先核实平台属性再解读。**
> 不要直接写进运营建议。

## 六、假期 / 大促效应

当期若含法定长假、平台大促，环比涨幅会被放大，必须**先剔除再解读**。

做法：同时给出

- 端游搜索环比（如 +72.9%）
- **全站搜索**同期环比（如 +53.3%）
- 端游占全站比例的变化（如 19.56% → 22.05%）

若端游增速 ≈ 全站增速，说明涨幅主要来自大盘；端游占比上升才代表端游自身变强。

> 2026-10-12 期（含国庆 10.1-10.7）：端游 +72.9%，全站 +53.3%，
> 端游占比 +2.49pp ⇒ 有假期加成，但端游确实跑赢大盘约 19.6 个百分点。

## 八、交付数字口径速查

| 指标 | 定义 |
|---|---|
| 端游搜索总量 | 命中词库的搜索次数合计（≠ 全站搜索量） |
| 端游命中款数 | 本期搜索次数 > 0 的游戏数 |
| 端游占比 | 端游搜索总量 ÷ 全站搜索总量 |
| 鲸云下载总量 | s2 表「本期下载」合计 |
| 三源共振 | 同一款游戏同时出现在 搜索 / 鲸云 / Steam 三个源 |
| 双源 | 命中其中两个源 |
