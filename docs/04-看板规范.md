## 一、样式基线：浅色优雅风

⛔ 用户明确否决过「深色霓虹风」，**不要**再换回去。

| 变量 | 值 | 用途 |
|---|---|---|
| `--bg` | `#f4f6fb` | 页面底色 |
| `--accent` | `#1e4ed8` | 主蓝 |
| `--grad` | 蓝色渐变 | hero / 总结卡 |
| `--up` | `#e03e3e` | **涨 = 红**（中国股市习惯） |
| `--down` | `#12a150` | **跌 = 绿** |

- 默认 `data-theme="light"`，右上角提供主题切换按钮
- hero 为圆角渐变横幅 + 网格纹理 + 徽章 chips

## 二、页面区块顺序（不能乱）

```
hero（标题 + 期次 + 徽章）
  ↓
KPI × 6
  ↓
图表两列（搜索 Top15 / 跨期对比 Top12）
  ↓
鲸云下载排行 Top12 / 鲸云 14 天逐日趋势
  ↓
Steam 在线 + 峰值 Top15
  ↓
品类分布（SVG 环形图）
  ↓
三源共振速览
  ↓
热点图文卡 × 12
  ↓
三源明细表（Tabs：s4 / s1 / s2 / s3）
  ↓
底部总结 sum-card
```

> ⚠️ **右侧定位条的顺序必须等于上面的区块顺序**。
> `spy()` 靠 `offsetTop` 单调递增判断当前区块，顺序错乱会导致滚动高亮跳段。

## 四、热点图文卡（固定 12 条）

### 版式

- 3 列网格，**12 条正好 4 行**，不留空位
- 每卡：顶部 16:9 封面（`aspect-ratio:16/9`）+ 左上角角标徽章 + 标题 + 描述 + 来源
- 顶部还有一条滚动 ticker（双份内容无缝循环）

### 12 条的构成

| # | 内容 | 封面字段 |
|---|---|---|
| 1–10 | 本期常规热点（大盘 / 退潮 / 新品 / 品类 / 竞品动作…） | `cover` 或 `viz` / `vizdata` |
| **11** | **📜 版号重点**（固定栏目，不可省） | `cover: "license"`（程序化信息图） |
| **12** | **🎮 移植候选**（固定栏目，不可省） | `cover4: [4 个 key]`（2×2 拼贴） |

### 封面字段四种形态

| 字段 | 效果 | 什么时候用 |
|---|---|---|
| `cover: "<key>"` | 单张真实 Steam 主视觉 | 有明确对应游戏 |
| `cover4: [k1,k2,k3,k4]` | 2×2 拼贴 | 移植候选（4 款游戏） |
| `viz: "daily"` | 用真实数据实时画图 | 大盘 / 趋势类 |
| `vizdata` | 用真实数据画数据封面 | 涨跌 / 品类类 |

> ⛔ **不要塞空洞占位图**。没有对应游戏就用数据画。
> 新增的 `cover` key 必须能被 `04b` 抓到 —— 走 `10_draft_hotspots.py` 时它自动写进
> `covers_plan.json`，由 `04b --plan` 读取；手写模式则要**同时**写进 `04b` 的 `COVERS` 字典。

### 12 条怎么来（半自动）

`10_draft_hotspots.py` 按固定槽位从 `data.json` 挑料并套模板句：

| # | 槽位 | 挑法 |
|---|---|---|
| 1 | 📈 大盘总览 | KPI：端游搜索 / 全站搜索 / 鲸云下载 三项环比 + 份额变化 |
| 2 | 🚀 搜索涨幅冠军 | `rise` 里涨幅最大且**基数 ≥ max(2 万, 搜索总量 0.4%)** |
| 3 | 📥 下载涨幅冠军 | `dl_rise` 里涨幅最大且当期 ≥ 300 |
| 4 | 🏆 搜索榜首 | `top_search[0]` |
| 5 | 🎮 Steam 在线王 | `top_steam[0]` |
| 6 | 🔗 三源共振 | `s4` 中搜索/下载/Steam 三端都有量的，按搜索量取最大 |
| 7 | 🆕 新游观察 | 本期发行 → 近一月 → 近一年，逐级退让，取在线最高 |
| 8 | 📉 退潮预警 | 搜索跌 ≥15% 且上期 ≥2 万 / 下载跌 ≥15% 且上期 ≥1500，取更狠的 |
| 9 | ⚠️ 跨端外溢 | 搜索涨 ≥100%、量 ≥8 万、但 Steam 名录查无此游 → 疑似非端游 |
| — | 📊 品类结构 | 第 9 条无外溢标的时的兜底（`cat` 前 5 品类） |
| 10 | 🎯 独立游戏王 | `独立游戏=="是"` 中在线最高 |
| 11 | 📜 版号重点 | ❌ **永远人工**，脚本留 `_needs_human` |
| 12 | 🎮 移植候选 | 触屏标签分 + 体积分 + 人气分开方 + 已有手游版一票否决 |

**同一款游戏不会在两个槽位重复出现**（内部有 `used` 去重）。

第 12 条的打分细则：`TOUCH_TAGS` 加权（卡组构筑/挂机/放置/殖民地模拟/经营 权重 3，
Roguelike/模拟/策略/解谜/休闲 权重 2，像素/单人 权重 1），体积 ≤4GB 越大越加分、
>8GB 扣分、未知扣 2 分；`MOBILE_ALREADY` 里**精确匹配**的扣 100 分（实质排除）。

> ⚠️ `MOBILE_ALREADY` 必须**精确匹配**。用子串会把新作误杀：
> `杀戮尖塔` 是 `杀戮尖塔2` 的子串，但后者是 2026 年新作、尚无手游版。
> （本项目在跨源匹配上踩过同一个坑，见 05-坑位清单 A 类）

### 三种状态

| 状态 | 判定依据 | 05 行为 | 08 行为 |
|---|---|---|---|
| 初稿 | 有 `_needs_human: true` | **拒绝出看板**（退出码 3） | — |
| 草稿 | 带 `--allow-draft` 出的板，`<body data-draft="N">` | 放行并打标记 | **BLOCK** |
| 已复核 | 无 `_needs_human` | 正常出板 | 走常规体检 |

### 版号取材

1. 查国家新闻出版署公布批次（**注意公布日期是否落在本期内**）
2. 抓三样：批次款数（国产/进口拆分）、**审批变更里「增加客户端」的名单**、年内累计数
3. 自查：本批数量 + 上期累计 == 本批之后累计
4. 若期内确实没发新批，照实写「截至期末尚未公布」，**不拿上一批冒充当期**

### 移植候选取材

1. 筛 `data.json` 的 `s3` 中 `独立游戏 == "是"`（数量每期不同，约 20~25 款）
2. 四条标准挑 4 款：**适配触屏 + 体积小 + 人气在线 + 尚无成功手游版**
3. 挂机 / 卡牌 / 模拟三类变现模型最成熟，优先

## 六、三源明细表（4 个 Tab）

| Tab | 内容 | 排序 |
|---|---|---|
| `s4` ⭐ | 三源关联重点表（**首项，默认展开**） | 不支持（值形如 `第8(9,858)`） |
| `s1` | 搜索源全量 | 支持 |
| `s2` | 鲸云源全量 | 支持 |
| `s3` | Steam 源 | 支持 |

### 重点表 `s4` 规则

- **已并入明细表**，不再是独立区块（⛔ 不要退回独立的 `#focus`）
- 行高 ≈ 22px（`td{padding:3px 8px;line-height:1.3}`）
- 按**源数降序**：三源 → 双源 → 单源
- **行数不得比上期少**（上期 29 行；低于 27 行视为漏标的）
- 判定/标签列 `td.clip` 单行省略 + `title` 看全文
- 「⤢ 全屏查看」按钮**仅在此 Tab 显示**，切到 s1/s2/s3 自动隐藏

## 七、回归测试（06）

`06_test_board.js` 用 jsdom 无头渲染，**55 项断言**：

- 各区块行数（**从 `data.json` 派生**，不是硬编码）
- 环形图 `path` 几何合法性
- 封面内嵌校验
- 定位条结构、旧区块防回归（`#focus` 必须为 0）
- Tab1 激活态、全屏按钮联动
- **热点固定 12 条 / 末两条栏目 / 每条都有主视觉**
- 可见文本无 `undefined` / `NaN` / `[object`
- 无 JS 运行时错误
- 5 条行为断言（过滤生效、Tab 切换联动）

### 改结构时必做两件事

1. **同步更新断言** —— 增删区块、改 id、改 Tab 数都要改
2. **反证验证** —— 故意把目标改坏，断言必须变红：

```bash
# 例：把 HOT 砍到 11 条 → 「热点条数」断言必须 ❌
node 06_test_board.js --board broken.html
```

> 断言里**不要写死会过期的数字**（上期 27 行、14 张图…），
> 否则每期都要手改，忘改就「红得没意义」，久了没人看。
