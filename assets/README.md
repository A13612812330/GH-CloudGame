# assets · 词库与元数据

## endgame_lib.json — 端游词库

```json
{
  "endgame": {
    "我的世界": ["我的世界", "MINECRAFT", "MC"],
    "OVERPEAK": ["OVERPEAK", "OVER PEAK", "超人模拟器", "巅峰崛起"]
  },
  "exclude": ["恐怖", "我的", "植物", "甜瓜"]
}
```

- **endgame**：游戏名 → 别名列表。搜索词命中任一别名即归到该游戏。
- **exclude**：绝不会被匹配的词（双字泛词、跨品类词）。

当前规模：**195 条**游戏。

### 补词的正确姿势

1. 先看 `01_prep_search_dl.py` 的输出：哪些高频搜索词**没被归到任何游戏**
2. 判断它是「某游戏的新别名」还是「无关泛词」
   - 是别名 → 加进 `endgame.<游戏名>`
   - 是泛词 → 加进 `exclude`
3. 改完**必须重跑 01**（词库只在 01 生效），并对比总命中量的变化

### 三条经验

| 经验 | 说明 |
|---|---|
| **别名要唯一** | 一个别名只能指向一个游戏，否则归属随机 |
| **泛词宁可排除** | `超人` 这种词会吃掉几十万无关搜索（实测 99,576 次，占某条目 31%） |
| **截断词归并不确定** | `OVER` 既可能是 OVERWATCH 也可能是 OVERPEAK；两期用同一词库时趋势不失真，但绝对归属存疑，报告里要注明 |

### ⚠️ exclude 是全局的

如果某游戏名**包含** `exclude` 里的词，它永远不命中。
例：`exclude` 有 `甜瓜`，则 `甜瓜游乐场` 无法计数。
补词前先检查这个冲突。

## steam_meta_seed.json — Steam 元数据种子

90 条 appid → 元数据，供**首次运行**（还没有历史交付物时）使用。

```json
{
  "4108000": {
    "cn": "机械狂欢", "en": "Machine Party", "dev": "...",
    "tags": "派对/恐怖/合作/PvP/独立", "date": "2026-07-30",
    "size": "1.35GB", "indie": "是",
    "min": "...", "rec": "", "peak": "22,629", "note": "..."
  }
}
```

- `02_extract_steam_meta.py` 会先读种子，再用产出目录下历史大报告的 ③Steam源**补空**
- 新游戏不在种子里 → 03 会报「历史元数据缺失 N 款」→ 在 04 的 `PATCH` 里补
- 种子随仓库更新，可以用自己积累的 `steam_meta.json` 覆盖（合并后字段应只增不减）
