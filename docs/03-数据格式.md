# 03 · 数据格式与自检

> 拿到新一期数据，**先跑 `00_probe_inputs.py` 看结构**，再跑后续步骤。

---

## 一、目录约定

```
<data_dir>/
├── 9.14-9.27/              ← 上期
│   ├── 搜索9.14-9.27.xlsx
│   └── 鲸云下载.xlsx
└── 9.28-10.11/             ← 本期
    ├── 搜索量9.28-10.11.xlsx
    ├── 鲸云下载.xlsx
    └── 云游戏注册.xlsx      ← ⛔ 不读
```

- 期目录名 = 期标签（`9.28-10.11`），脚本据此定位。
- **文件名不必统一**，`_cfg.py` 会按关键词自动探测：
  - 搜索：文件名含「搜索」
  - 下载：文件名含「下载」/「鲸云」/「云游戏下载」
  - 含「注册」的一律跳过
- 同一目录有多个候选时，取**最近修改**的那份。

---

## 二、搜索表（神策导出）

### sheet 结构

| sheet | 用途 | 关键列 |
|---|---|---|
| `明细数据` | 清洗用这个 | `行为时间`、`搜索内容`（统一大小写）、`…总次数` |
| `汇总数据` | 自洽校验用 | `搜索内容`、`总和`、`均值`、`最大`、`最小` |

### 列名特点

列名常带前缀，如 `[（虚拟）搜索_搜索按钮点击事件] 搜索内容`。
脚本按**关键词**定位列（含「搜索内容」「总次数」），不依赖完整列名。

### 日期粒度

「明细数据」每期含 **2 个日期列**（通常是两个周一），每个日期列代表**该周汇总**。

---

## 三、下载表（鲸云导出）

### sheet 结构

| sheet | 用途 | 关键列 |
|---|---|---|
| `明细数据` | 清洗用这个 | `行为时间`、`游戏名称`、`下载开始` |
| `汇总数据` | 自洽校验 | `游戏名称`、`合计` |
| `明细报表` | 交叉核对 | 列名 = 该期各日期 |

### 两个注意点

1. **游戏名带「（云游戏）」后缀**，需去掉再匹配。
2. **日期粒度不固定**：可能是 14 天逐日，也可能是 2 列周汇总。**每次都要探测**（见 [02-数据口径](02-数据口径.md) 第二节）。

### 指标列

找含「**下载开始**」的列。若该关键词一次都没出现 ⇒ **文件很可能放错了**（见第五节）。

---

## 四、自洽性校验（最重要的一步）

每个表都有「汇总」和「明细」两个口径，**两者必须相等**：

```
搜索：汇总数据.总和 合计  ==  明细数据.总次数 合计
下载：汇总数据.合计 合计  ==  明细数据 各日合计
```

### 实测基准值

| 期次 | 全站搜索总量 | 端游命中（**当前词库**） | 下载总量 |
|---|---|---|---|
| 9.14 – 9.27 | 8,884,570 | 1,737,746 | 71,795 |
| 9.28 – 10.11 | 13,621,985 | 3,003,769 | 104,846 |

> ⚠️ **不能拿旧报告的数字直接比。** 上期报告发布时记录的端游命中是 **1,649,636**
> （当时的词库），补了 3 款词条后重算为 **1,737,746**。
> 跨期对比必须用**同一套词库重算两期**，否则环比里会混进词库变更的影响。

### 快速校验命令

```bash
python 00_probe_inputs.py     # 会打印每个 sheet 的 shape 与列名
python 01_prep_search_dl.py   # 会打印两期的总量与命中量
```

若下载表的汇总与明细**完全相等**但数值与上期一模一样 ⇒ 大概率是上一期的文件。
若汇总 ≠ 明细 ⇒ 文件内部有缺失，不要用。

## 五、放错文件的识别（真实事故）

### 事故一：下载表放了上一期的数据

- 症状：汇总 = 104,846，明细合计 = 71,795，**内部不自洽**
- 且逐日总量与上一期完全一致
- 判据：**汇总 ≠ 明细**

### 事故二：下载表其实是搜索表的副本

- 症状：三个 sheet **逐字节相同**；全表搜不到「下载开始」，却有 3 处「搜索按钮点击事件」
- 判据：**文件大小与搜索表完全相同 + 缺少「下载开始」关键词**

### 处置流程

1. 报错给数据提供方，说明「汇总/明细不一致」或「缺少下载开始列」
2. **不要**自行用汇总数据凑一份报告（口径会错）
3. 重新导出后，先跑自洽校验再继续

## 六、输出文件

| 文件 | 位置 | 说明 |
|---|---|---|
| `search_agg.csv` | `<tmp_dir>/` | ① 搜索聚合（游戏/本期/上期/环比/词数/品类/代表词） |
| `dl_agg.csv` | `<tmp_dir>/` | ② 下载聚合（游戏/本期/上期/环比） |

| `端游三源周报看板_<起止>.html` | `<out_dir>/` | 单文件看板 |

## 七、Excel 五表

| sheet | 内容 |
|---|---|
| ① 搜索关键词源 | 端游名 / 本期搜索 / 上期搜索 / 两期合计 / 环比 / 关键词数 / 品类 / 代表词 |
| ② 鲸云源 | 游戏 / 本期下载 / 上期下载 / 两期合计 / 环比（全量） |
| ③ Steam源 | 非网游；中文名 / appid / 标签 / 发行日期 / 在线 / 峰值 / 独立 / 备注 |
| ④ 三源关联重点表 | 搜索 × 鲸云 × Steam 交叉标注（**必须保留**） |
| ⑤ 概览 | 数据源与口径 + 核心结论 + 运营建议 |

> ⛔ ①② 的列名**不要**写成 W1/W2 或「两周总搜索」——那是已废弃的期内口径。

## 八、Steam 元数据字段

`steam_meta.json` 每条：

```json
{
  "4108000": {
    "cn": "机械狂欢", "en": "Machine Party",
    "dev": "Mike Klubnika/GDeavid",
    "tags": "派对/恐怖/合作/PvP/独立",
    "date": "2026-07-30", "size": "1.35GB", "indie": "是",
    "min": "Win11/双核2.4GHz/8GB/RX6500XT或GTX1660/1GB",
    "rec": "", "peak": "22,629",
    "note": "8/4峰值2.26万后回落，未进前100"
  }
}
```

- 按优先级合并：**种子文件** → 历史大报告 ③Steam源（越新越优先）
- 缺失字段不报错，04 的 `PATCH` 会补一部分
